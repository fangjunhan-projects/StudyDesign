## 1. PH Model — Monthly Enrollment Input Option

### UI Change
Added a radio button toggle under **Accrual & Follow-up**:

- **Constant rate** (default): existing inputs — Accrual Duration (months) and Accrual Rate (patients/month)
- **Monthly enrollment counts**: a single text field for comma-separated monthly enrollment numbers (e.g. `2, 3, 4, 5, 23, 67, 2, 45, 8, 12, 11, 12`)

### Backend Change
Before building the `getSampleSizeSurvival` args, the server now resolves accrual inputs based on the selected method:

- **Constant rate**: `accrualTime = c(0, accrual_time)`, `accrualIntensity = accrual_rate` (unchanged behaviour)
- **Monthly enrollment**: `accrualTime = seq(0, n_months - 1)`, `accrualIntensity = monthly_enroll_vector`

where `n_months` is the length of the user-supplied monthly enrollment vector, and each element maps directly to the patients enrolled in that month.

## 2. NPH Model — Monthly Enrollment Input Option

### UI Change
Added the same radio button toggle under **Accrual & Follow-up**:

- **Constant rate** (default): existing inputs — Accrual Duration (months) and Accrual Rate (patients/month)
- **Monthly enrollment counts**: a text field for comma-separated monthly counts, with a note that values are converted to relative proportions for gsDesign2

### Backend Change
The server now resolves the `enroll_rate` object based on the selected method:

- **Constant rate**: `define_enroll_rate(duration = accrual_time, rate = accrual_rate)` (unchanged)
- **Monthly enrollment**: 
  ```r
  define_enroll_rate(
    duration = rep(1, length(monthly)),
    rate     = monthly / sum(monthly)
  )
  ```
  Counts are converted to **relative enrollment rates** (proportions summing to 1) because `gs_design_ahr` scales enrollment internally to achieve the target N. The `total_time` (accrual + follow-up) is also derived from the vector length rather than a manual input.

## 3. New Tab: PH — Stratified (rpact)

### Background
rpact does not natively support stratified sample size calculation. The standard approach is to compute a **weighted average hazard ratio** across strata and pass it as a single `hazardRatio` to `getSampleSizeSurvival`. The weighted average is computed on the log scale using enrollment proportions as weights:

```r
hr_weighted <- exp(sum(rel_props * log(hr_strata)))
```

### UI Change
Added a new top-level tab **"PH — Stratified (rpact)"** with:

- Same group sequential design controls as the standard PH tab (K, alpha, beta, info fractions, IA types, alpha/beta spending functions)
- **Number of Strata** selector (2–6), with dynamic per-stratum inputs:
  - Stratum name
  - Enrollment proportion (%)
  - Hazard ratio (trt/ctrl)
- Live display of the computed **weighted average HR** (updates as inputs change)
- Same accrual options (constant rate or monthly enrollment counts) and follow-up/dropout inputs

### Backend Change
- Normalises enrollment proportions to sum to 1
- Computes `hr_weighted = exp(Σ rel_prop_i × log(HR_i))`
- Passes `hr_weighted` as `hazardRatio` to `rpact::getSampleSizeSurvival`
- Design Details output shows per-stratum breakdown alongside the weighted HR used

### Output tabs
Stage Details, Boundaries (z), Boundaries (HR), Boundary Plot, Design Details

## 4. New Tab: NPH — Stratified (gsDesign2)

### Background
`gsDesign2` natively supports stratification via the `stratum` argument in `define_enroll_rate` and `define_fail_rate`. Each stratum can have its own enrollment proportion, baseline hazard, and delayed treatment effect parameters. `gs_design_ahr` computes the average hazard ratio weighted across strata.

### UI Change
Added a new top-level tab **"NPH — Stratified (gsDesign2)"** with:

- Same group sequential design controls as the standard NPH tab (K, alpha, beta, spending functions)
- **Number of Strata** selector (2–6), with dynamic per-stratum inputs:
  - Stratum name
  - Enrollment proportion (%)
  - Median survival — control (months)
  - Delay duration (months)
  - HR during delay
  - HR after delay (steady-state)
- Common accrual (duration + rate), follow-up, dropout rate, allocation ratio
- Analysis calendar times and alpha/beta spending (sfLDOF, sfLDP, sfHSD)

### Backend Change
- Enrollment proportions normalised to sum to 1; passed to `define_enroll_rate` with `stratum`
- Per-stratum failure rates built using the delayed treatment effect model and passed to `define_fail_rate` with `stratum`
- `gs_design_ahr` computes the stratified AHR internally

```r
# Enrollment
define_enroll_rate(
  duration = rep(accrual_time, n_strata),
  rate     = rel_props,
  stratum  = strat_names
)

# Failure rates (one pair of rows per stratum)
define_fail_rate(
  duration     = c(delay_1, Inf, delay_2, Inf, ...),
  fail_rate    = c(lambda_1, lambda_1, lambda_2, lambda_2, ...),
  hr           = c(hr_early_1, hr_late_1, hr_early_2, hr_late_2, ...),
  dropout_rate = dropout_mo,
  stratum      = c("S1","S1","S2","S2",...)
)
```

### Output tabs
Stage Summary, Boundaries, Design Details
